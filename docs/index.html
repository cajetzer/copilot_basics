2ChooseCollaborate, plan first, or run autonomously

6RecoverStop, revise, or rewind where supported

Fast troubleshooting

Most early failures are missing context, weak boundaries, or late review.

Started without the real artifactOpen or attach the file, issue, pull request, error, screenshot, or repository context.
Switched surfaces without a reasonStay where the work already is unless another client offers a genuinely better next step.
Vague outcomeAdd scope, constraints, and evidence instead of prescribing random implementation details.
Wrong autonomy levelCollaborate for unfamiliar work, plan first for ambiguity, and automate only a well-defined task.
Agent is heading the wrong waySteer immediately, narrow the action, or stop the task instead of waiting.
Only reviewed the summaryOpen the real diff, session log, checks, tests, and pull request changes.
Assumed every session follows every deviceChoose a cloud session for device independence; local remote control still depends on the original machine.
Was your last weak result caused by missing context, unclear evidence, the wrong collaboration style, or insufficient review?
Presenter cue: Keep the tone nonjudgmental. Most corrections do not require a better model or a different client; they require the real context, a clearer brief, earlier steering, or better verification.

Choose the collaboration style

Task clarity and risk matter more than the client.

Collaborate closely Use when

The code is unfamiliar, local behavior matters, or you expect to make decisions while work proceeds.

Plan first Use when

The work spans files, services, or repositories, or requirements and architecture need agreement before implementation.

Run autonomously Use when

The outcome and evidence are well defined and the local, remote, or cloud environment is appropriately controlled.

VS Code / CLI

GitHub.com

Copilot app

Agent-produced change

export function parseTags(input) {
  return input
    .split(",")
    .map((tag) => tag.trim())
    .filter(Boolean);
}

The interaction differs; the engineering habit is the same: steer early instead of reviewing an avoidable mistake later.

Focused tests added

describe("parseTags", () => {
  it("parses normal input", () => {
    expect(parseTags("alpha,beta"))
      .toEqual(["alpha", "beta"]);
  });

  it("trims and ignores empty entries", () => {
    expect(parseTags("alpha, beta,,gamma"))
      .toEqual(["alpha", "beta", "gamma"]);
  });

  it("returns an empty array for empty input", () => {
    expect(parseTags(""))
      .toEqual([]);
  });
});

Local-session caveat

  • Synced local history is not the same as cloud execution.
  • Remote control can make a running local session steerable from web or mobile.
  • The original machine must remain online for remotely controlled local work.
Choose a cloud environment when the task must keep running independently of the original device.
Presenter cue: Do not promise that every local session seamlessly moves between devices. Cloud-session continuity, synced local history, and remote control are distinct capabilities.

Closing recap

Seven habits for useful Copilot outcomes on any surface

  • 1Start where the work already is.
  • 2Use the context the surface already supplies.
  • 3Brief outcome, scope, constraints, and evidence.
  • 4Choose collaboration and autonomy deliberately.
  • 5Steer early when an assumption is wrong.
  • 6Review actual changes, commands, tests, and unknowns.
  • 7Use a cloud session when the work must follow you across devices.
The best surface is the one that already has the context and controls your next step needs.
